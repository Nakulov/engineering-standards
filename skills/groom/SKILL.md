# Груминг

Груминг заканчивается проектными решениями. Как делать (эпик, исследование, отказ, разбивка) — решает план.

## Процесс

1. **Понимание идеи.** Изучи контекст проекта: файлы, документацию, последние коммиты по теме.
   - Открытые задачи по теме — продолжи существующую, не заводи дубль.
   - Закрытые «не будет сделано» и «Отклонено» соседних задач — не возвращайся к отклонённому без новой причины.
   - «Границы» ROADMAP, если он есть, — тема за границами обсуждается отдельно.

   Вопросы — по одному, инструментом с вариантами. Фокус: назначение, ограничения, критерии успеха, точки интеграции.
2. **Исследование подходов.** Когда идея понятна — 2–3 подхода с компромиссами по шаблону ниже.
3. **Представление дизайна.** После выбора подхода — секции: архитектура, компоненты, поток данных, обработка ошибок, тестирование.
   - Секция — не больше 300 слов; подтверждение пользователя после каждой, не всю разбивку сразу.
   - Неприменимая — явно: «не применима: <почему>» (пример: «Поток данных — не применима: шаблон только читается»).
   - Что-то не складывается — откатись назад.
4. **Следующий шаг** — выбирает пользователь:
   - **план** — в новой сессии: запиши итог груминга в журнал и выведи «Продолжи в новой сессии из папки проекта: `/plan <N>`». Сам скилл плана здесь не вызывай: план в этой сессии перечитывал бы весь груминг на каждом ходу;
   - **сразу в работу** — в этой сессии, без плана и `execute`.

   Правка настолько проста, что план, агенты-исполнители и ревью обойдутся дороже её самой, — скажи об этом и предложи «сразу в работу» с причиной. Пример: опечатка «опесание» → «описание» в одной строке. Решает пользователь.

   Вместе со списком всплывших тем (раздел «Отслеживание задач») выведи список «касается #N: <что>»: решения, задевающие соседние задачи и скиллы; спроси, куда их записать.

   Итог груминга — в журнал `plans/journal/groom-<N>.md` (задачи нет — `groom-<тема>.md`; папка вне git), при любом выборе на шаге 4:
   ```
   Контекст груминга:
   - Задача: [#N или тема] — [одна фраза]
   - Найденные файлы: `путь` — зачем
   - Выбранный подход: [название] — почему; отклонённые: [название] — почему
   - Проектные решения: [по секциям дизайна, по пункту]
   - Открыто: [что не решено и кто решает]

   Всплывшие темы:
   - завести в Backlog: …

   Касается других задач:
   - касается #N: …
   ```

### Шаблон подходов

```
Выбираем: [что решаем — одной фразой, на примере из проекта].

**Вариант А: [название]** (рекомендую — [почему, с источником])
- как работает: [на конкретном примере из проекта]
- плюсы: ...
- минусы: ...
- объём: [≈ N файлов / PR]

**Вариант Б: [название]**
- как работает: ...
- плюсы: ...
- минусы: ...
- объём: ...

Что выбираешь?
```
- 2 или 3 варианта — без варианта, придуманного для счёта.
- Невыбранные — в «Отклонено» с причиной из их минусов.

## Ключевые принципы

1. **Один вопрос за раз, пример сначала.**
2. **Выбор из вариантов** — когда возможно. Вопрос в окне инструмента понятен сам по себе: названо, о чём речь, у каждого варианта — короткое описание (окно может не показывать текст выше).
3. **YAGNI** — минимизируй объём.
4. **Исследуй альтернативы** — 2–3 варианта, если они реально есть; вариант один — скажи, почему других нет.
5. **Пошаговая валидация** — дизайн секциями, подтверждение каждой.
6. **Будь гибким** — возвращайся и уточняй; возврат к согласованному — явным вопросом «это меняет согласованное решение N, меняем?».
7. **Имей своё мнение** — объясняй почему, но решение за пользователем.
8. **Дублирование или абстракция** — код повторяется: спроси, дублирование (проще, нет связанности) или абстракция (DRY, но сложнее); компромиссы — до решения.
9. **Факт — с источником** — `файл:строка`, опыт, вывод команды; перед объяснением решения — перечитай задачу и процитируй; без источника — «предполагаю».
10. **Ничего не меняешь** — ни файлы проекта (код, скиллы, черновики, конфиги), ни тела других задач; исключение — свой файл в журнале `plans/journal/groom-<N>.md`. Груминг — разговор и решения; запись решений своей задачи — по процессу хранения решений. Решение касается соседней задачи или скилла — не правь их, а собери «касается #N: <что>» и выведи на шаге 4.

## Отслеживание задач

- После каждого подтверждения — строка прогресса: что записано, что дальше; следующую подтему сам не открывай.
- Темы, всплывшие по ходу, — держи списком «завести в Backlog: …» и дописывай в журнал `groom-<N>.md` сразу, не в конце: при сжатии контекста список не потеряется; внутри текущей задачи их не грумь; на шаге 4 — выведи список и спроси, заводить ли их.
- Инструмент задач — если есть, веди в нём шаги процесса и секции дизайна дополнительно; его может не быть.
