# Выполнение плана

Скилл выполняет план последовательно через изолированных агентов.

- **Последовательно** — задачи плана по порядку; следующая начинается, когда предыдущая закончена.
- **Изолированный агент** — новый агент на каждую задачу, без истории сессии; читает план целиком, получает заголовок секции своей задачи.
- **Изоляция — только по контексту:** все агенты работают в одной рабочей копии; отдельная копия на каждого агента не нужна — параллельной работы нет.
- **Основная сессия код не пишет** — запускает агентов по очереди; план правит исполнитель `plan-executor`.

## Вход

Номер задачи и slug плана — `<N> <slug>`: аргументом от скилла плана или явно от пользователя (`execute 48 execute`; напоминание — строка «План: …» в теле задачи). План — `plans/<slug>.md` на ветке `task/<N>-<slug>` или `long/<N>-<slug>`.
- Аргументов нет — спроси; план сам не ищи.
- Готовность задачи проверяет `task start` (шаг 0): закрыта, эпик, не Groomed / In progress, открытые блокеры — команда откажет; сообщи её ответ и остановись.

## Процесс

0. **Где и ветка плана** — до чтения плана: план лежит только на ветке задачи.
   1. Спроси инструментом вопросов:
      ```
      Вопрос: Где выполняем блок плана «<slug>» (#<N>)?
      Заголовок: Где

      • Здесь — в текущей папке проекта: папка переключится на ветку задачи и занята до конца блока.
      • Ворктри — отдельная копия `.claude/worktrees/<slug>` на ветке задачи: основная папка остаётся как есть.
      ```
      Копия `.claude/worktrees/<slug>` в основной папке проекта уже есть — не спрашивай: «Ворктри», выбор сделан на прошлом блоке.
   2. Какая ветка есть: `git ls-remote origin task/<N>-<slug> long/<N>-<slug>` — только чтение.
   3. «Здесь»: `task/…` — `task start <N> <slug>`; `long/…` — `task start <N> <slug> --long`. Команда переключается на существующую ветку, перематывает отставшую до `origin` и ставит In progress. Ветка разошлась с `origin` — команда откажет: сообщи её ответ и остановись; не чини. «Ворктри» — вызови скилл `worktree` с `<N> <slug>` (`--long` для long-ветки): он создаёт или открывает копию и переводит в неё сессию.
   4. Нет ни одной — сообщи «план не сохранён: нет ветки `task/<N>-<slug>` или `long/<N>-<slug>`» и остановись.
   5. Файла `plans/<slug>.md` на ветке нет: есть `plans/done/<slug>.md` — план выполнен и убран, сообщи об этом и остановись; нет и там — сообщи и остановись; не угадывай.
1. **Объём.** Прочитай план, найди текущий блок. Сообщи одной строкой: «План `<путь>`: блок k из M — N задач». Незакрытых блоков нет — сразу шаг 8.
   Открой раздел запуска в журнале `plans/journal/<slug>.md` основной папки проекта (нет файла — создай с заголовком `# Журнал: <название плана>`): `## Запуск <ГГГГ-ММ-ДД ЧЧ:ММ> — блок «PR k: <что даёт>»`.
2. **Где выполняем** — выбрано на шаге 0. «Ворктри» — сессия уже в копии: рабочая папка агентов (`git rev-parse --show-toplevel`) — корень копии.
3. **Ветка.**
   - Ворктри, один блок — ничего: ветку взял скилл `worktree`.
   - Ворктри, блоков больше одного — `task start <N> <slug>-pr<k> --from long/<N>-<slug>` в копии, без `--worktree`: ветка блока — в той же копии.
   - Здесь, один блок — ничего: ветка задачи уже взята на шаге 0.
   - Здесь, блоков больше одного — `task start <N> <slug>-pr<k> --from long/<N>-<slug>`: ветка блока от long-ветки (шаг 0 стоит на long-ветке).
4. **Цикл задач.** Повторяется, пока в текущем блоке есть задача (см. ниже). Следующий блок — только следующим запуском, в новой сессии, после слияния PR этого блока. Каждая итерация:
   1. Перечитай план — агенты меняют его каждую итерацию.
   2. Найди первую единицу работы. Нет — переходи к п. 4.7.
   3. Сообщи, какую задачу агент берёт в работу: выведи секцию целиком.
   4. Запусти нового агента `plan-executor` по имени, без истории сессии. Аргументы: абсолютный путь к плану; рабочая папка — `git rev-parse --show-toplevel` (корень текущей рабочей копии); блок — заголовок `## PR k` как есть; задача — заголовок секции как есть; номер попытки; путь к журналу; при повторе — итог прошлой попытки (его запись из журнала).
   5. Сначала ответ агента, потом план:
      - В ответе агента «⚠️ ошибка в плане» — в любой его записи, в том числе в «Приёмке» после закрытой задачи, — останови цикл сразу, без оставшихся попыток: новый агент упрётся в тот же план. Сообщи по шаблону ошибки в плане.
      - Иначе перечитай план: все `- [ ]` задачи закрыты (`[x]`)? Да — сообщи: «Задача N из плана завершена»; следующая итерация.
      - Нет — новый агент, на вход — итог прошлой попытки как есть (ошибки сборки, коммита, правил). Попытка без новых `[x]` — проваленная, даже если агент написал «готово».
   6. 3 проваленные попытки одной задачи — останови цикл целиком: следующие задачи строятся на этой. Сообщи по шаблону провала.
   7. Все единицы закрыты — переходи к ревью.

   Ошибка агента — не повод остановиться, а повод для новой попытки. Цикл останавливается только в трёх случаях: блок выполнен, 3 провала одной задачи или ошибка в плане.

   **Скилл ничего не делает сам:** не читает код, не правит ошибки, не диагностирует, не исправляет. Вся работа с кодом — агентом; осталась ошибка после агента — новый агент с её контекстом.

   Шаблон провала — без анализа:
   ```
   Задача <N> «<название>» не выполнена за 3 попытки.
   Не закрыто:
   - [ ] <шаг>
   Попытка 1: <итог агента — цитатой>
   Попытка 2: …
   Попытка 3: …
   ```

   Шаблон ошибки в плане — без анализа:
   ```
   Задача <N> «<название>» остановлена: ошибка в плане.
   <ответ агента — цитатой>
   ```

5. **Ревью** — один раз на план: только в запуске последнего блока, после п. 4.7; не последний блок или цикл остановлен (3 провала, ошибка в плане) — не запускай.
   1. Запусти параллельно, по имени, без истории сессии — только этих: `implementation-reviewer` — реализация (изменения достигают цели плана; сделано то, что в плане, и ничего сверх) и `test-reviewer` — тестирование (тесты проверяют поведение, крайние случаи покрыты). Каждому: путь к плану, рабочая папка, база — `git merge-base origin/dev HEAD` (начало ветки плана; одинаково для одного блока и нескольких), путь к журналу. Только чтение — ревью ничего не правит.
   2. Дождись обоих. Агент упал или ответил не по шаблону — не перезапускай: в итоге «<зона>: не выполнено — <ответ агента>»; ревью цикл и PR не блокирует.
   3. Сведи находки механически, без оценки: одинаковые `файл:строка` и проблема — одна находка, зоны через запятую, оценка — более высокая (К выше В, В выше М). Пронумеруй: К1, В1, М1… Сводка для журнала (шаг 7) — по шаблону:
      ```
      К1. `файл:строка` — <проблема> (<зоны>)
          Влияет: <на что и чем грозит>
          Исправить: <как — одним предложением, без кода>
          Вопрос: <зона: номер и название>
      ```
   4. Шкала находок — как у `plan-reviewer`: Критичные / Важные / Минорные.
   5. Сообщи итог — только первая строка каждой находки:
      ```
      Ревью: замечаний нет. Проверено: <зоны>.
      ```
      ```
      Ревью: <N> находок — критичных <К>, важных <В>, минорных <М>.
      К1. `файл:строка` — <суть> (<зона>)
      В1. …
      Полный список — <путь к журналу>.
      ```
   6. Находки пока не исправляем — собираем в журнал для анализа.
6. **Стандарты** — вместе с шагом 5 и при тех же условиях: один раз на план, в запуске последнего блока.
   1. Запусти агента `standards-reviewer`: путь к плану, рабочая папка, база — та же, что в шаге 5. Он проверяет по банку знаний — стандартам наших проектов, отдельно от общего ревью. Только чтение — ничего не правит.
   2. Упал или ответил не по шаблону — не перезапускай: «Стандарты: не выполнено — <ответ агента>».
   3. Находка с теми же `файл:строка` и проблемой, что в ревью, — не повторяй: «= ревью К1».
   4. Шкала находок — Критичные / Важные / Минорные.
   5. Сообщи итог — после итога шага 5:
      ```
      Стандарты: замечаний нет.
      ```
      ```
      Стандарты: банк знаний не найден — проверено только по образцам существующего кода.
      ```
      ```
      Стандарты: <N> находок — критичных <К>, важных <В>, минорных <М>.
      К1. `файл:строка` — <суть>
      В1. …
      Полный список — <путь к журналу>.
      ```
   6. Находки пока не исправляем — собираем в журнал для анализа.
7. **Итог блока.** Допиши в раздел запуска журнала: `### Ревью`, `### Стандарты` — находки полностью; `### Итог блока` — резюме ниже.
   Черновик PR — `task pr --title «…» --body-file <файл> --check «команда»…` (блоков больше одного — `--part`, в long-ветку):
   - план из ветки убирает сама команда: PR в `dev` (один блок) — копия в `plans/done/`, коммит «Убрать план»; PR блока в long-ветку план не трогает;
   - тело — по шаблону PR: «Что меняет PR» — заголовок блока, «Изменения» — его «Объём», «Вручную» — ручные шаги (✋);
   - `--check` — команды из «Валидации» записей журнала;
   - к ревью (`task pr --ready`) переводит пользователь после просмотра.

   Сообщи резюме; блоков больше — «PR k готов: слей его и продолжи в новой сессии из папки проекта: `/execute <N> <slug>`»:
   ```
   Блок «PR k: <что даёт>» выполнен: <N> из <N> задач; осталось блоков: <M − k>.
   Один блок — «План „<название>“ выполнен; план — `plans/done/<slug>.md`»; блоков больше одного и этот последний — «после слияния PR продолжи в новой сессии: `/execute <N> <slug>` — для `task final`».
   Ревью: <замечаний нет | К <к>, В <в>, М <м> | после последнего блока>.
   Стандарты: <замечаний нет | К <к>, В <в>, М <м> | после последнего блока><, только по образцам — нет банка знаний>.
   Где: <ветка> (<здесь | ворктри <путь>>).
   Вручную: <нет | N шагов>
   - <задача> — <шаг>
   Журнал: <путь>.
   PR: <ссылка> (черновик).
   ```
8. **Итог плана** — план из нескольких блоков, все закрыты (после слияния PR последнего блока): `task final <N> --title «…» --body-file <файл> --check «команда»…` — long-ветка → `dev`; план команда убирает сама — копия в `plans/done/`. Сообщи: «План „<название>“ выполнен: M блоков; план — `plans/done/<slug>.md`».

## Ключевые принципы

1. **Чистый контекст** — каждый агент получает чистый контекст, без накопленного состояния предыдущих задач.
2. **Сессия только отслеживает** — скилл ничего не меняет, кроме журнала и места плана после итога; ветки, статусы, коммит удаления плана и PR — только нашими командами `task`.
3. **План не модифицирует** — это делают агенты.
4. **Код не модифицирует** — это делают исключительно агенты.
5. **Провал — только перезапуск** — агент провалился или оставил сломанный код: перезапусти нового агента, на вход — итог прошлой попытки как есть; до 3 попыток на задачу. Сам не исследуешь и ничего не исправляешь.
6. **Состояние — только в плане** — каждую итерацию перечитывай план; номера задач и прогресс в памяти сессии не держи.
7. **Находки — как есть** — сводишь только механически: одинаковые `файл:строка` и проблема; не проверяешь, не оцениваешь, не выбрасываешь; кода для этого не читаешь.

Блок — секция плана `## PR k`; текущий блок — первый сверху, в котором есть строка, начинающаяся с `- [ ]`.
Задача — секция `### Задача N` или `### Приёмка` внутри текущего блока, в которой есть строка, начинающаяся с `- [ ]`.
- `## Состав работ` — не задача: сводка тех же задач.
- Смотри строки, начинающиеся с `- [ ]`, а не `[ ]` в любом месте: в «Прогрессе» `[x]` есть в тексте правила.
