# Выполнение плана

Скилл выполняет план последовательно через изолированных агентов.

- **Последовательно** — задачи плана по порядку; следующая начинается, когда предыдущая закончена.
- **Изолированный агент** — новый агент на каждую задачу, без истории сессии; читает план по частям — оглавление, общие разделы, своя задача; получает блок и заголовок задачи.
- **Изоляция — только по контексту:** все агенты работают в одной рабочей копии; отдельная копия на каждого агента не нужна — параллельной работы нет.
- **Основная сессия ничего не делает сама** — не читает код и план целиком, не правит, не диагностирует; меняет только журнал; ветки, статусы, PR — командами `task`. Код и план правит исполнитель `plan-executor`; осталась ошибка после агента — новый агент с её контекстом.

## Вход

Номер задачи и slug плана — `<N> <slug>`: из строки `/execute <N> <slug>`, которую печатает скилл плана (`decompose`), или от пользователя (напоминание — строка «План: …» в теле задачи). План — `plans/<slug>.md` на ветке `task/<N>-<slug>` или `long/<N>-<slug>`.
- Аргументов нет — спроси; план сам не ищи.
- Готовность задачи проверяет `task start` (шаг 0): закрыта, эпик, не Groomed / In progress, открытые блокеры — команда откажет; сообщи её ответ и остановись.

## Процесс

0. **Где и ветка плана** — до чтения плана: план лежит только на ветке задачи.
   1. Спроси инструментом вопросов:
      ```
      Вопрос: Где выполняем блок плана «<slug>» (#<N>)?
      Заголовок: Где

      • Здесь — в текущей папке проекта: папка переключится на ветку задачи и занята до конца блока.
      • Ворктри — отдельная копия `.worktrees/<slug>` на ветке задачи: основная папка остаётся как есть.
      ```
      Копия `.worktrees/<slug>` в основной папке проекта уже есть — не спрашивай: «Ворктри», выбор сделан на прошлом блоке.
   2. Какая ветка есть: `git ls-remote origin task/<N>-<slug> long/<N>-<slug>` — только чтение.
   3. «Здесь»: `task/…` — `task start <N> <slug>`; `long/…` — `task start <N> <slug> --long`. Команда переключается на существующую ветку, перематывает отставшую до `origin` и ставит In progress. Ветка разошлась с `origin` — команда откажет: сообщи её ответ и остановись; не чини. «Ворктри» — вызови скилл `worktree` с `<N> <slug>` (`--long` для long-ветки): он создаёт или открывает копию и переводит в неё сессию.
   4. Нет ни одной — сразу п. 5, без `task start`.
   5. Ветки нет или на ней нет `plans/<slug>.md` — смотри `plans/done/<slug>.md` в основной папке проекта: туда копию кладут `task pr` и `task final`, в копии ворктри этой папки нет. Есть — сообщи «план выполнен и убран — `plans/done/<slug>.md`»; нет — «план не сохранён: <нет ветки `task/<N>-<slug>` или `long/<N>-<slug>` | на ветке нет `plans/<slug>.md`>». В обоих случаях остановись; не угадывай.
1. **Где работаем** — сразу после шага 0, командами, не по памяти:
   - рабочая папка — `git rev-parse --show-toplevel`: здесь работают команды и агенты;
   - основная папка — родитель `git rev-parse --path-format=absolute --git-common-dir`: в ней журнал и `plans/done/`.

   Выведи одной строкой, абсолютными путями:
   ```
   Где: <здесь | ворктри> — рабочая `<путь>`, основная `<путь>`, ветка `<ветка>`, журнал `<основная>/plans/journal/<slug>.md`.
   ```
   Дальше «рабочая папка», «основная папка» и «журнал» — пути из этой строки. Сомневаешься, где сессия, — повтори обе команды.
2. **Объём.** `grep -nE '^(## |### |- \[ \])' <план>` — заголовки и незакрытые шаги; по выводу найди текущий блок (см. «Единица работы»). Сообщи одной строкой: «План `<путь>`: блок k из M — N задач». Незакрытых блоков нет — сразу шаг 7.
   Открой раздел запуска в журнале (нет файла — создай с заголовком `# Журнал: <название плана>`): `## Запуск <ГГГГ-ММ-ДД ЧЧ:ММ> — блок «PR k: <что даёт>»`.
3. **Ветка.**
   - Ворктри, один блок — ничего: ветку взял скилл `worktree`.
   - Ворктри, блоков больше одного — `task start <N> <slug>-pr<k> --from long/<N>-<slug>` в копии, без `--worktree`: ветка блока — в той же копии.
   - Здесь, один блок — ничего: ветка задачи уже взята на шаге 0.
   - Здесь, блоков больше одного — `task start <N> <slug>-pr<k> --from long/<N>-<slug>`: ветка блока от long-ветки (шаг 0 стоит на long-ветке).
4. **Цикл задач.** Повторяется, пока в текущем блоке есть задача. Следующий блок — только следующим запуском, в новой сессии, после слияния PR этого блока. Каждая итерация:
   1. `grep -nE '^(## |### |- \[ \])' <план>` — каждую итерацию заново: агенты меняют план. План целиком не читай.
   2. По выводу найди первую задачу текущего блока (см. «Единица работы»). Нет — переходи к п. 4.7.
   3. Сообщи, какую задачу агент берёт в работу: заголовок задачи и её незакрытые шаги из вывода `grep`, без кода.
   4. Запусти нового агента `plan-executor` по имени, без истории сессии. Аргументы: абсолютный путь к плану; рабочая папка; блок — заголовок `## PR k` как есть; задача — заголовок секции как есть; номер попытки; журнал; при повторе — итог прошлой попытки (его запись из журнала).
   5. Сначала ответ агента, потом план:
      - В ответе агента «⚠️ ошибка в плане» — в любой его записи, в том числе в «Приёмке» после закрытой задачи, — останови цикл сразу, без оставшихся попыток: новый агент упрётся в тот же план. Сообщи по шаблону ошибки в плане.
      - Иначе повтори `grep` из п. 4.1: в секции задачи не осталось `- [ ]`? Да — сообщи: «Задача N из плана завершена»; следующая итерация.
      - Нет — новый агент, на вход — итог прошлой попытки как есть (ошибки сборки, коммита, правил). Попытка, после которой незакрытых строк в секции не стало меньше, — проваленная, даже если агент написал «готово».
   6. 3 проваленные попытки одной задачи — останови цикл целиком: следующие задачи строятся на этой. Сообщи по шаблону провала.
   7. Задач в блоке не осталось — блок последний в плане: шаг 5; иначе — шаг 6.

   Ошибка агента — не повод остановиться, а повод для новой попытки. Цикл останавливается только в трёх случаях: блок выполнен, 3 провала одной задачи или ошибка в плане.

   Шаблон провала — без анализа:
   ```
   Задача <N> «<название>» не выполнена за 3 попытки.
   Не закрыто:
   - [ ] <шаг>
   Попытка 1: <итог агента — цитатой>
   Попытка 2: …
   Попытка 3: …
   ```

   Шаблон ошибки в плане — без анализа:
   ```
   Задача <N> «<название>» остановлена: ошибка в плане.
   <ответ агента — цитатой>
   ```

5. **Ревью и стандарты** — один раз на план: только в запуске последнего блока, после п. 4.7. Не последний блок или цикл остановлен (3 провала, ошибка в плане) — не запускай. Прочитай `review.md` рядом с этим скиллом и выполни его шаги; затем — шаг 6.
6. **Итог блока.** Допиши в раздел запуска журнала: `### Ревью`, `### Стандарты` — находки полностью (только последний блок); `### Итог блока` — резюме ниже.
   Черновик PR — `task pr --title «…» --body-file <файл> --check «команда»…` (блоков больше одного — `--part`, в long-ветку):
   - план из ветки убирает сама команда: PR в `dev` (один блок) — копия в `plans/done/`, коммит «Убрать план»; PR блока в long-ветку план не трогает;
   - тело — по шаблону PR: «Что меняет PR» — заголовок блока, «Изменения» — его «Объём», «Вручную» — ручные шаги (✋);
   - `--check` — команды из «Валидации» записей журнала;
   - к ревью (`task pr --ready`) переводит пользователь после просмотра.

   Сообщи резюме:
   ```
   Блок «PR k: <что даёт>» выполнен: <N> из <N> задач; осталось блоков: <M − k>.
   Ревью: <замечаний нет | К <к>, В <в>, М <м> | после последнего блока>.
   Стандарты: <замечаний нет | К <к>, В <в>, М <м> | после последнего блока><, только по образцам — нет банка знаний>.
   Где: <ветка> (<здесь | ворктри <путь>>).
   Вручную: <нет | N шагов>
   - <задача> — <шаг>
   Журнал: <путь>.
   PR: <ссылка> (черновик).
   Дальше: <…>
   ```
   «Дальше» — одно из трёх:
   - блок не последний — «слей PR k и продолжи в новой сессии из папки проекта: `/execute <N> <slug>`»;
   - план из одного блока — «план выполнен, копия — `plans/done/<slug>.md`»;
   - последний блок из нескольких — «после слияния PR продолжи в новой сессии: `/execute <N> <slug>` — для `task final`».
7. **Итог плана** — план из нескольких блоков, все закрыты (после слияния PR последнего блока): `task final <N> --title «…» --body-file <файл> --check «команда»…`. Команда создаёт ветку `task/<N>-final` от long-ветки, убирает на ней план (копия — в `plans/done/` основной папки) и открывает PR `task/<N>-final` → `dev` с `Closes #N` сразу к ревью; в long-ветку ничего не пушит. Сессия остаётся на `task/<N>-final`: правки по ревью — на ней, повтор `task final` вливает в неё свежую long-ветку; после слияния — `task done` оттуда, он удаляет и long-ветку. Сообщи:
   ```
   План „<название>“ выполнен: M блоков; план — `plans/done/<slug>.md`.
   Где: task/<N>-final (<здесь | ворктри <путь>>).
   PR: <ссылка> (к ревью).
   После слияния — `task done` из `task/<N>-final`: удалит и long-ветку.
   ```

## Единица работы

<!-- >>> execute:unit -->
Блок — секция плана `## PR k`; текущий блок — первый сверху, в котором есть строка, начинающаяся с `- [ ]`.
Задача — секция `### Задача N` или `### Приёмка` внутри текущего блока, в которой есть строка, начинающаяся с `- [ ]`.
- `## Состав работ` — не задача: сводка тех же задач.
- Смотри строки, начинающиеся с `- [ ]`, а не `[ ]` в любом месте: в «Прогрессе» `[x]` есть в тексте правила.
