# setup

```
setup
setup --confirm
setup --check
```

## Когда звать
Настроить репозиторий текущей папки по стандарту. Одна команда для нового и существующего репозитория: шаг применяет только недостающее, повторный запуск ничего не меняет.

- без опций — применить недостающее; удаляющие шаги только печатаются;
- `--confirm` — применить, включая удаляющие шаги;
- `--check` — только сверить, ничего не менять.

## Коды выхода
- `--check`: `0` — репозиторий соответствует стандарту, `1` — есть отклонения.
- Без `--check`: `1` — есть отклонения или удаляющие шаги ждут `--confirm`.
- Остальное — как в [README.md](README.md): отказ — `1`, сбой — `2`.

## Что проверяет
До первого шага:
1. Права токена `gh`: `repo` и `project`.
2. Права администратора репозитория.

Затем шаги стандарта по очереди: каждый печатает строки о своей части репозитория.

## Отказы
Код выхода 1. Текст — как печатает `setup`, с подстановками `<права>`, `<право>`.

| Текст | Причина | Что делать |
|-------|---------|------------|
| `у токена gh нет прав <права> — выполните: gh auth refresh -s <право> …` | у токена `gh` нет прав `repo` или `project` | — |
| `нет прав администратора репозитория — настройки меняет его владелец` | у пользователя нет прав admin | попросить владельца запустить `setup` |
