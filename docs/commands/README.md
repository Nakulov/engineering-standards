# Команды процесса

Команды `task` и `setup` из `scripts/` — механика процесса: ветки, PR, доска, настройка репозитория. Читают:
- человек — когда выбирает команду или команда отказала;
- скиллы и агенты — ссылаются на файл команды вместо пересказа её поведения.

## Файлы

| Команда | Файл | Когда звать |
|---------|------|-------------|
| `task start` | [start.md](start.md) | начать работу над задачей: ветка, статус In progress |
| `task commit` | [commit.md](commit.md) | закоммитить задачу плана: файлы — из сообщения |
| `task pr` | [pr.md](pr.md) | открыть черновик PR или перевести его к ревью |
| `task done` | [done.md](done.md) | после слияния PR: свежий `dev`, ветка удалена, статус Done |
| `task final` | [final.md](final.md) | итоговый PR long-задачи в `dev` |
| `task new` | [new.md](new.md) | завести задачу по шаблону типа в Backlog |
| `task groomed` | [groomed.md](groomed.md) | груминг закончен: задача из Backlog в Groomed |
| `task plan` | [plan.md](plan.md) | сохранить план в ветку задачи |
| `task stage` | [stage.md](stage.md) | завести веху этапа |
| `setup` | [setup.md](setup.md) | настроить репозиторий по стандарту или сверить настройки |

## Коды выхода

- `0` — команда выполнена.
- `1` — отказ: процесс не пускает (задача не Groomed, грязное дерево, нет PR). Текст отказа объясняет причину; что делать — в разделе «Отказы» файла команды. Шаги до отказа — в «Что проверяет» файла команды.
- `2` — сбой: сеть, `gh`, неверные аргументы, неизвестная команда, ошибка скрипта. Текст — «сбой скрипта: … — подробности: TASK_DEBUG=1»; повторите с `TASK_DEBUG=1` перед командой — напечатается стектрейс. Неверные аргументы — сверьте со строкой использования в файле команды.

У `setup --check` свои коды — в [setup.md](setup.md).

## Общие опции

- `-C <папка>` — первым аргументом: выполнить команду в другой папке, как `git -C`; например `task -C .worktrees/<slug> pr …`.
