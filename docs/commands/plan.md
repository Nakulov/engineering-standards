# task plan

```
task plan <N> <slug> [--long] --issue-parts <файл>
```

## Когда звать
Утверждённый план `plans/<slug>.md` нужно сохранить в ветку задачи в `origin` без PR. Рабочая папка и текущая ветка не трогаются: коммит делается во временной копии.

- `--long` — ветка `long/<N>-<slug>` вместо `task/<N>-<slug>`.
- `--issue-parts <файл>` — части плана для тела задачи: каждая попадает в раздел тела с тем же заголовком, между метками `<!-- план -->`.

Что делает:
- план — коммит «Добавить план: <название>» в ветку; повтор — «Обновить план: <название>»; план не изменился — «план не изменился — коммита нет»;
- в тело задачи — строка «План: ветка `<ветка>`, `plans/<slug>.md`» и части из `--issue-parts`;
- локальный `plans/<slug>.md` удаляется;
- задача из Backlog переводится в Groomed (как `task groomed`), другой статус не меняется.

## Что проверяет
1. Заданы `<N>`, `<slug>` и `--issue-parts <файл>`. Иначе сбой (код 2) со строкой использования.
2. Есть `plans/<slug>.md` с заголовком «# название» и файл частей. Иначе сбой (код 2).
3. Задача открыта.
4. Тип задачи не эпик.
5. Заголовки из файла частей есть в теле задачи, метки `<!-- план -->` парные.
6. Ветка не открыта в рабочей папке (выполнение не начато).
7. Локальная ветка плана, если есть, отправлена в `origin` и не расходится с ним.
8. Задача есть ровно на одной доске (после сохранения плана).

Если план сохранён, а тело задачи или статус обновить не удалось — сбой (код 2): повторить `task plan` или `task groomed <N>`.

## Отказы
Код выхода 1. Текст — как печатает `task`, с подстановками `<N>`, `<ветка>`, `<папка>`.

| Текст | Причина | Что делать |
|-------|---------|------------|
| `#<N> закрыта` | задача закрыта | — |
| `#<N> — эпик: план — на подзадачу` | тип — эпик | `task plan` с номером подзадачи |
| `ветка <ветка> открыта в <папка> — выполнение начато, план правит исполнитель` | ветка плана уже взята в работу | править план в `<папка>` в ходе выполнения |
| `локальная <ветка> не отправлена в origin — отправьте её или удалите` | есть локальная ветка без `origin` | — |
| `локальная <ветка> расходится с origin/<ветка> — сведите вручную` | локальная и удалённая разошлись | `git log <ветка>...origin/<ветка>` — что разошлось |
| `в задаче нет раздела «<раздел>» — исправьте заголовок в файле частей` | заголовок в `--issue-parts` не совпал с разделом тела задачи | — |
| `в разделе «<раздел>» метка <!-- план --> без пары — поправьте тело задачи` | в теле задачи одна метка без закрывающей | — |
| `#<N> не на доске — добавьте её на доску проекта` | задачи нет на доске | — |
| `#<N> на нескольких досках` | задача на двух и более досках | убрать со всех досок, кроме доски репозитория |
