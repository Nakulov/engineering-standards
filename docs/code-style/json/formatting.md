# Оформление — JSON-FMT

Формат правил и префиксы — [README.md](README.md).

### JSON-FMT-1. Раскладка — как выводит `json.dumps(data, ensure_ascii=False, indent=2)` плюс перевод строки в конце
Почему: одно определение раскладки, которое умеет вывести любой язык. Спорить о переносах не о чем, а проверка простая: разобрать файл, записать заново и сравнить с исходным побайтно. Раскладка с пределом ширины строки, как у Prettier, зависит от длины строки: переименование одного ключа перекладывает соседние строки, и дифф шумит.
Проверка: проверка JSON
```jsonc
// Запрещено — массив в одну строку, отступ 4
{
    "name": "Сборка",
    "tags": ["release", "nightly"]
}

// Разрешено — каждое поле и каждый элемент массива на своей строке, отступ 2
{
  "name": "Сборка",
  "tags": [
    "release",
    "nightly"
  ]
}
```
Пустые `[]` и `{}` остаются в одну строку, так их выводит `json.dumps`.

### JSON-FMT-2. Кодировка — UTF-8, кириллица как есть, без `\u`-экранирования
Почему: экранированный текст не прочитать ни в файле, ни в диффе.
Проверка: проверка JSON — сравнение по JSON-FMT-1 с `ensure_ascii=False` ловит экранирование
```jsonc
// Запрещено
{
  "title": "Сборка"
}

// Разрешено
{
  "title": "Сборка"
}
```

### JSON-FMT-3. Имена полей — lowerCamelCase
Почему: одно написание во всех файлах, и оно совпадает с именами свойств Kotlin при разборе JSON в классы.
Проверка: ревью
Ключ-значение — например, имя записи в словаре — пишется так, как того требуют данные: такой ключ не поле, а данные.

```jsonc
// Запрещено
{
  "retry_count": 3,
  "ReleaseNotes": "…"
}

// Разрешено — поля в lowerCamelCase; ключи словаря colors — данные, их написание задаёт проект
{
  "retryCount": 3,
  "releaseNotes": "…",
  "colors": {
    "Primary": "#3366FF"
  }
}
```

### JSON-FMT-4. Порядок ключей задаёт автор; ключи не сортируются
Почему: порядок помогает читать файл — главное сверху: `name`, затем `type`, затем `description`. Сортировка по алфавиту поставила бы `description` выше `name`. Порядок полей в файле — как в `properties` его схемы.
Проверка: ревью; проверка JSON порядок сохраняет — `json.dumps` без `sort_keys`
```jsonc
// Запрещено — отсортировано по алфавиту, имя ушло вниз
{
  "description": "Ночная сборка",
  "name": "nightly",
  "type": "release"
}

// Разрешено — как в properties схемы
{
  "name": "nightly",
  "type": "release",
  "description": "Ночная сборка"
}
```
