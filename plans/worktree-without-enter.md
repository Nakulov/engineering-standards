# Execute работает в копии без перехода сессии

**Цель:** `execute` с выбором «Ворктри» ведёт журнал в основной папке: сессия не переходит в копию, агенты работают в копии по абсолютным путям.
**Архитектура:** скилл `worktree` только создаёт копию и выводит путь — без `EnterWorktree`. Сессия `execute` остаётся в основной папке и передаёт агентам рабочую папку; команды — `-C <рабочая папка>`, файлы — `<рабочая папка>/<путь>`. Правило про пути — маркерный блок `agents:working-folder` в исполнителе и трёх ревьюерах, сверяется `MarkersSpec`.
**Стек:** Markdown скиллов и агентов; Kotlin + Kotest (`scripts`) для проверки маркеров.

---

## Ограничения
- Не трогать: код `task` (`scripts/src/main/**`) — решение вписывается в текущие команды (`-C` уже есть), груминг #96, решение 7.
- Плагин из другого репозитория не ломается: только `task -C`, без `scripts/task` и `cd` (`rules/bash-commands.md`).
- Изменено при плане: сессия `execute` — только из основной папки; при ручном `/worktree` подсказка «запусти `/execute` из основной папки» вместо «откройте `claude` в `<путь>`» (груминг, решение 6) — одна модель без исключений; запуск из копии `execute` останавливает (шаг 0).
- Изменено при плане: блок называется `agents:working-folder`, а не `execute:working-folder` (груминг, решение 10) — префикс `execute` уже связан с парой `skills/execute/SKILL.md` → `agents/plan-executor.md` (`scripts/src/test/kotlin/io/github/nakulov/standards/task/MarkersSpecData.kt:10`); источник `plan-executor.md` для `execute:*` потребовал бы от ревьюеров копию `execute:unit`.

## Обзор
- Что реализуется: `/worktree` без `EnterWorktree`; `execute` в основной папке с явной рабочей папкой; правило абсолютных путей для агентов.
- Какую проблему решает, что даёт: сессия после `EnterWorktree` не может писать вне копии — журнал `execute` и `plans/done/` в основной папке недоступны (#96).
- Как встраивается: шаг 0–1 `execute` фиксирует пути в строке «Где», дальше все команды и агенты берут пути только из неё.
- Критерии цели:
  - в `skills/` и `agents/` нет `EnterWorktree`;
  - `execute` запускается только из основной папки (из копии — остановка с путём основной); вычисляет рабочую папку из выбора и проверяет её; `task start` блока, `pr`, `final`, `done` и база ревью — через `-C <рабочая папка>`;
  - исполнитель и три ревьюера содержат блок `agents:working-folder`, копии 1 в 1 — `MarkersSpec` зелёный;
  - вручную: `/execute` «Ворктри» создаёт журнал, основная папка чистая, правки — в копии.

## Обзор решения
- Подход и архитектура: А из груминга — убрать `EnterWorktree`; сессия `execute` в основной папке, агентам — абсолютный путь рабочей папки.
- Решения:
  - сессия `execute` — всегда в основной папке: в начале шага 0 проверка `--show-toplevel` сессии = родитель `--git-common-dir`, иначе остановка с путём основной папки;
  - основная папка — родитель `--git-common-dir`, как сейчас (`skills/execute/SKILL.md:40`);
  - рабочая папка — из выбора шага 0, не из `--show-toplevel`: сессия всегда в основной;
  - проверка рабочей папки — `git -C <рабочая папка> rev-parse --show-toplevel` равен пути (груминг, решение 9);
  - в строке «Где» добавлен план `<рабочая>/plans/<slug>.md` — `grep` шагов 2 и 4.1 и агенты берут его отсюда;
  - правило путей — маркерным блоком, не ручным дублированием (груминг, решение 10).
- Как вписывается в систему: команды `task` не меняются, меняется только папка, которую им передают.
- Обратная совместимость: не нужна — внутренние скиллы плагина; копии, созданные раньше, открываются тем же `task start --worktree`.
- Запасной: Б — журнал и `plans/done/` в копию — переходим, если `task -C <копия>` из основной папки не работает для `pr`/`final`/`done`.
- Отклонено:
  - Б — журнал в копию: `task done` удаляет копию вместе с журналом; шаг 0.5 ищет `plans/done/` в основной; правка Kotlin и тестов.
  - два режима `/worktree` (с `EnterWorktree` и без): условие в скилле, баг остаётся для ручного режима.
  - проверка `git -C <основная> status` после блока: ложные тревоги на правки пользователя.
  - `execute` из сессии в копии (подсказка «откройте `claude` в `<путь>`»): журнал пишется вне папки сессии — вероятны запросы доступа; два входа вместо одного.
  - ручное дублирование правила путей в агентах: расхождение не поймать (#48).
