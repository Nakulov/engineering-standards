# Описание команд в docs

**Цель:** описать команды `task` и `setup` в `docs/commands/` — когда звать, что проверяет, отказы и что делать — и заменить пересказ команд в скиллах ссылками.
**Архитектура:** раскладка «`README.md` + файл на команду» по образцу `docs/code-style/kotlin/README.md`; документ пишется по коду команд (`scripts/src/main/kotlin/io/github/nakulov/standards/task/command/*.kt`) и справке `task --help`, `setup --help`; код `task` не меняется. Второй PR заменяет в четырёх скиллах описание поведения команд ссылкой `${CLAUDE_PLUGIN_ROOT}/docs/commands/<команда>.md`.
**Стек:** Markdown; источник — Kotlin-код `scripts/`.

---

## Ограничения
- Не трогать: `scripts/` — подход А «только раскладка»: отказ ищется по тексту из терминала, код и спеки не меняются (груминг #34); проверка — `git diff --stat origin/dev -- scripts/` пуст.
- Не трогать: `agents/plan-reviewer.md` — `task pr --ready` там пример критерия (стр. 44, 51), не пересказ; агенту не передаётся «Base directory» (груминг #34, решение 5).
- В текстах скиллов нет «(#N)» (правило проекта); примеры — абстрактные (репозиторий публичный).
- `docs/commands/` на памятку `docs/workflow.md` (#15) не ссылается — ссылка в одну сторону (груминг #34, решение 4).
- Блоки меток `<!-- >>> … -->` в скиллах не трогаем — правки PR 2 вне меток.

## Обзор решения
- Подход и архитектура: из груминга — А «только раскладка»: `README.md` + файл на команду с разделами «Когда звать», «Что проверяет», «Отказы».
- Решения:
  - папка `docs/commands/`, не `docs/task/` — `setup` тоже команда, а «task» в репозитории значит и задачу (груминг, решение 1);
  - все 10 команд, `stage.md`, не `stage-create.md` — подкоманды `stage` добавятся без переименования (решение 2);
  - коды выхода — один раз в `README.md`; в «Отказах» — только код 1; сбои (код 2) — общим абзацем (решение 3);
  - «Что делать» не повторяет подсказку из текста отказа — только недостающее, иначе «—» (решение 3);
  - вывод при успехе не описывается, кроме строк, на которые опираются скиллы (последняя строка `--worktree` — путь копии) (решение 3);
  - общий отказ (`Board.kt`, `Publisher.kt`, …) — строкой в файле каждой команды, которая его печатает: человек ищет по команде, которую звал;
  - PR 2: ссылкой заменяется что делает команда (проверки, тексты отказов, побочные действия); в скилле остаётся когда звать, с какими аргументами, реакция агента, разбираемые строки вывода (решение 5).
- Как вписывается в систему: `docs/` — документы процесса; скиллы плагина читают `${CLAUDE_PLUGIN_ROOT}/docs/commands/…` — подстановка в тексте скилла проверена (#3, «Опыты 2026-11-14»).
- Обратная совместимость: не нужна — новые документы, поведение команд и скиллов не меняется.
- Запасной: нет — подход груминга подтверждён, альтернатива Б отклонена.
- Отклонено:
  - Б «раскладка + ID отказов» (`TASK-START-2` в выводе `task`) — правка всех отказов в коде и спеках, вторая задача внутри #34; на отказы не ссылаются замечания ревью;
  - ссылки в обе стороны с памяткой #15 — до #15 ссылка на несуществующий файл или правка `docs/commands/` в PR #15;
  - относительная ссылка `../../docs/commands/…` от «Base directory» — агент вычисляет путь сам, опытом не проверено.
