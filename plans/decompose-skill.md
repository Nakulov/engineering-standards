# Скилл decompose вместо скилла плана

**Цель:** скилл плана переезжает в `skills/decompose/` (вызов `/decompose <N>`) с пятью решениями «Пересмотра» задачи #46.
**Архитектура:** точечные правки текста скилла по решениям груминга 1–5, по задаче плана на этап или раздел; `plan-reviewer` — только строка detekt и «Вход»; синхронность маркерных блоков скилла и агента закрепляет новый тест `MarkersSpec`.
**Стек:** Markdown-скиллы и агенты плагина Claude Code; тест — Kotlin, Kotest + kotestkit (`shouldReturnTest`), Gradle `:scripts:test`.

## Ограничения
- Переезд — только `git mv skills/plan skills/decompose` и `name: decompose` в шапке: история файла сохраняется.
- Не переименовывать: агенты `agents/plan-*.md`, папку `plans/` — решение груминга 1.

- Правки точечные, скилл целиком не переписывается — отклонено на груминге.
- Остаются: `model: sonnet` у скилла и агента (решение 4г), шаблон плана и таблица частей — в `SKILL.md` (решение 4в); примеры в тексте — абстрактные (репозиторий публичный).

## Обзор решения
- Подход и архитектура: точечные правки по решениям груминга, задача плана — этап или раздел скилла; агент — только где его задевают правки скилла.
- Решения:
  - тест маркеров — отдельной спекой `MarkersSpec`, по образцу `TemplatesSpec` — один логический файл проверки на файлы репозитория;
  - правка «Входа» агента — в одной задаче с этапом 5 скилла: меняются вместе;
  - принципов семь, не шесть — *изменено при плане*: в решении 5в перечислено семь, «6» — опечатка (подтверждено пользователем 2026-11-20);
  - строка 127 (`plan:coverage`, «Критерии готовности» задачи) не переписывается по 3г — *изменено при плане*: блок — копия в агенте, правка агента вне ограничения;
  - второй план на задачу #N — «заменить» сохраняет slug: повтор `task plan` делает «Обновить план» в той же ветке (`PlanCommand.kt:101`), другой slug — вторая ветка (`PlanCommand.kt:30–32`); открытый вопрос #46 закрыт;
  - задачи «Вход и рамка» и «Принципы» — до этапов: этапы ссылаются на принципы по имени («Возврат к согласованному»).
- Обратная совместимость: не нужна — `/plan` и `/engineering-standards:plan` перестают работать, решение груминга 1.
- Как вписывается в систему: groom → `/decompose <N>` → `task plan` → `/execute <N> <slug>` — без изменений, кроме имени.
- Запасной: переписать раздел скилла целиком — переходим, если после точечных правок раздел противоречит сам себе.
- Отклонено:
  - переписать скилл целиком — риск сломать согласованное (груминг);
  - оставить `plan` с вызовом `/engineering-standards:plan` — по привычке `/plan` молча включает встроенный режим (#66);
  - вынести шаблон и таблицу в файлы — экономия ≈ 7 тыс. кэшированных токенов, цена — отдельный вызов с полным контекстом (4в);
  - убрать `model: sonnet` — пилоты #52, #53: экономия без заметной разницы в качестве (4г).

## Технические детали
- Блок маркера: `<!-- >>> plan:<имя> -->\n<текст><!-- <<< plan:<имя> -->`; регулярка с обратной ссылкой `\1` на имя.
- `findMarkerMismatches()` — объединение имён из обоих файлов, по алфавиту; имя попадает в список, если текст отличается или блока нет в одном из файлов.
- `findSkillMarkers()` — имена блоков скилла по алфавиту: пустой скилл (файл без маркеров) не даст ложно-зелёного `findMarkerMismatches()`.
- Нет файла — `FileNotFoundException`, тест красный: переезд не завершён.

  ```kotlin
  package io.github.nakulov.standards.task

  import java.io.File

  private const val SKILL = "skills/decompose/SKILL.md"
  private const val AGENT = "agents/plan-reviewer.md"

  // Блок: `<!-- >>> plan:<имя> -->` + перевод строки + текст + `<!-- <<< plan:<имя> -->`; `\1` — то же имя.
  private val BLOCK = Regex(
      pattern = "<!-- >>> (plan:[a-z-]+) -->\\n(.*?)<!-- <<< \\1 -->",
      option = RegexOption.DOT_MATCHES_ALL,
  )

  /** Имена блоков `plan:*`, чей текст в скилле и агенте ревью расходится или есть только в одном файле. */
  fun findMarkerMismatches(): List<String> {
      val skill = blocks(path = SKILL)
      val agent = blocks(path = AGENT)
      return (skill.keys + agent.keys).sorted().filter { name -> skill[name] != agent[name] }
  }

  /** Имена блоков `plan:*` скилла по алфавиту — пустой скилл не даёт ложно-зелёного сравнения. */
  fun findSkillMarkers(): List<String> = blocks(path = SKILL).keys.sorted()

  private fun blocks(path: String): Map<String, String> {
      val text = File(System.getProperty("task.repoRoot"), path).readText()
      return BLOCK.findAll(input = text).associate { match -> match.groupValues[1] to match.groupValues[2] }
  }
  ```
